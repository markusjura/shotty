## What is decided

Build the full requested replacement in one implementation effort, including native testing on studio. Markus narrowed the scope on 25 September 2026: all implementation and verification in this PR stays on studio; m1 synchronization, installation, and fleet testing belong in a separate PR after implementation is complete. Do not stop after a capture-only MVP or treat preview limitations as omissions from the app. Do not wait for Markus to make ordinary implementation choices, tune numeric defaults, or test behavior the agent can exercise itself.

Markus explicitly reinforced low resource consumption and performance during implementation. Keep the design simple: bound concurrent image work and buffers, release streams/tasks/timers on every terminal path, keep idle CPU near zero, and profile repeated sessions for leaks. Measurements must justify additional optimization machinery; a growing cache or successful single run does not establish bounded memory.

After the measured frozen-window acquisition improvement from 322/330 ms to 244/252 ms p50/p95 on the same window set, Markus accepted the remaining delay if no easy further fix exists. Preserve exact frozen-window pixels, retain bounded concurrency, and show a cancellable preparing state while acquisition runs. The 100 ms target remains an aspiration for this path, not a gate requiring more optimization machinery. These timings apply to the measured seven-window desktop, not every window set.

The requested capture modes, editor tools, thumbnail behavior, settings, native blue accent, System/Light/Dark, and default menu-bar-only lifecycle are fixed. The prototype's single-row editor and flat Settings hierarchy are approved. Translate these into native SwiftUI/AppKit components; do not reproduce browser control styling.

Use macOS 26.0 as the deployment target, Apple Silicon, Swift 6 strict concurrency, and a single Xcode app target with focused tests. Use `local.markus.Shotty` as the stable bundle identifier unless an existing installed Shotty identity is found before first signing. Do not change the identifier after permission grants. Use Apple Development signing through the free account if available. Paid membership is not authorized and is not the default plan.

## Complete interaction and output rules

- A selected object's style controls edit that object; tool defaults edit new-object defaults. Persist the last new-object defaults across launches. Reset applies to the current tool, not every tool. Start new documents with Select.
- Keep all currently specified direct manipulation, multi-selection, crop, undo, text input, drag export, and accessibility behavior. The only thumbnail context commands are Open Editor, Copy Image, Save to Folder, Save As, and Dismiss. Canvas context commands are limited to existing select/edit/duplicate/arrange/delete functionality; no unrelated CleanShot commands are imported.
- While thumbnails are intentionally hidden, captures remain in the session store and Show Thumbnails makes them reachable. An editor window is unique per capture. Capture never blocks because another editor is open.
- Copy/save/show-thumbnail/open-editor are independent output choices. Freeze their values at capture invocation. Apply output independently per result when Fullscreen targets all displays. An error does not invalidate successful sibling outputs.
- Persist the immutable source plus document revision before promising that unexported work is retained. Normal quit with active captures offers Keep for next launch, Discard, or Cancel; default Keep. Next launch restores intentionally retained captures without a crash warning. An interrupted manifest produces Restore/Discard. This is recovery of the active session, not a searchable screenshot library.
- A file promise or save renders a snapshot of the requested document revision. Edits made during export remain unsaved. Success updates only that revision's saved/copied state. A failed export retains the document and shows a specific recovery action. Never use a later edit's revision as proof of export.
- Default filenames use `Shotty YYYY-MM-DD at HH.mm.ss.png`; collisions append `-2`, `-3`, etc. Templates support date, time, and capture type only, with a live example and filesystem-safe normalization. Save As explicitly chooses format/destination. Detect externally changed associated output files and offer Replace, Save As, or Cancel.
- General settings use the configured screenshot destination for image export; OCR has independent copy/review/save toggles and writes UTF-8 text. OCR uses accurate on-device recognition, automatic languages, and line breaks preserved by default. Cancellation or a newer unrelated clipboard write prevents a late automatic replacement.
- Shortcut settings must cover every advertised command through the shared registry. Commands without a useful default remain assignable rather than receiving invented global combinations. Only capture and explicit thumbnail-management commands can register globally; tool keys and editor commands stay local. The plan's distinct capture defaults avoid silently taking over macOS/CleanShot keys.

## Engineering questions to resolve without product reapproval

These are experiments, not preferences to ask Markus to guess. Record measured results and fix failures before moving the affected feature to complete. Escalate only if the required behavior cannot be delivered through supported APIs without materially changing scope, cost, or permissions.

1. Frozen window pixels. Prove that the image selected under the frozen window overlay is exactly the isolated image exported, including occluded regions and shadow. Evaluate per-window snapshot acquisition before showing the freeze surface and bound its latency/memory. Multiple captures need not be temporally atomic, but no frozen preview may export a later live frame. Desktop cropping is not a substitute for isolated-window capture. If supported APIs cannot meet both semantics, present the measured conflict and concrete alternatives before changing this requirement.
2. Universal scrolling. Use captured pixels, not per-app adapters. Establish reliable alignment, stationary-band handling, reverse-scroll recovery, repeated-row ambiguity, and physical-versus-injected scroll input. Observe mouse scrolling without requesting Input Monitoring or Accessibility in the manual-only path; verify this in a fresh permission state. If this cannot be done with supported mouse-event observation, resolve it explicitly before adding a permission.
3. Bounded export. Validate the 30,000-pixel/120-second defaults together with width and memory limits. Size buffers with overflow checks and reject or pause before memory exhaustion. The final encoder's memory use must be measured; disk-backed tiles alone do not prove bounded final export memory.
4. Signing and updates. Reuse the free identity, build a signed test app, and verify install, capture permissions, and an updated build on studio. Defer m1 to the separately requested fleet PR. No certificate, provisioning, or Gatekeeper result is assumed from successful compilation alone.

| --- | --- |
| Native capture | Synthetic animated/hover targets prove freeze consistency; mixed-scale and negative-origin geometry; isolated/shadowed window pixels; cancellation; own-panel exclusion; all output combinations. |

Pixel fixtures detect duplicate/missing seams, not merely a successful return value. |

| Accessibility and finish | VoiceOver and keyboard-only routes, semantic icons, native hit targets, high contrast, reduced transparency/motion, no toolbar wrapping, light/dark screenshots at actual display scale. |
| Performance | Record the plan's p50/p95 latency and memory/CPU targets on studio and m1, with cold starts separate. Fix main-thread stalls and unbounded work; do not substitute preview timings. |
| Fleet release | Verify the signature, actual first launch, per-Mac permissions, a rebuilt update, preference continuity, and rollback. Produce versioned signed ZIP, install instructions/script, validation report, and known limitations. Keep secrets out of the repository. |
