Prototype limits: what is real here and what is simulated
  • Real: the editor draws on an HTML canvas over a synthetic sample image rendered at 2x. Drag creation for rectangle, ellipse, line, arrow, redact, spotlight and crop (any direction, 4 px threshold, Shift for square, circle or 45° lines), live preview, the tool stays active after drawing.
  • Real: Select (V) picks the nearest outline, drags to move (Shift locks an axis), resizes with the blue handles or line endpoints, arrow keys nudge (Shift 10 px), Backspace deletes. Escape cancels a drag; ⌘Z and ⇧⌘Z or ⌘Y undo and redo one gesture at a time.
  • Real: counters number sequentially; text is typed inline where you click in a multiline field (Return adds a line; ⌘Return, Escape or clicking outside finishes and keeps text; tool letters are not intercepted while typing); zoom (⌘+ ⌘- ⌘0 ⌘1) keeps pointer coordinates correct; crop applies with Enter and is undoable.
  • Real: Done stores the editable state per capture card and returns to the desktop; reopening a card restores its annotations and crop, and Done recreates a card that was closed while editing. Every mock capture shares one synthetic source image. Thumbnail miniatures still show that source; they do not render the edits.
  • Real: redaction reads the source pixels. Pixelate averages blocks and adds per-block noise; Blur uses a browser gaussian over padded source samples; Solid covers. Both effects only obscure visually and make no recoverability guarantee. Strength changes with the slider or [ and ].
  • Simulated: capture (area, window, fullscreen, scrolling, OCR), permissions, the menu bar item, settings persistence, shortcut registration, Copy and Save. Nothing is written to the clipboard or disk. Display choices are illustrative; real pointer-driven relocation across monitors is not demonstrated.
  • Settings show a flat layout with browser-native checkboxes, radio buttons, and menus. The macOS app uses SwiftUI Settings, a native sidebar and Form, system colors, SF Symbols, and system dialogs. Browser controls, titlebar, materials, focus rings, and typography are approximations, not custom-control requirements for the app.
  • Scrolling: Start → scroll manually or click Auto Scroll → Done is interactive. Manual scrolling hides Auto Scroll for this capture; a new capture restores it. Stopping automation on manual input is a Shotty proposal. The region handles are illustrative, the miniature repeats synthetic content, and no screen stitching or reliable end detection runs here.
  • Missing: real ScreenCaptureKit capture, window and scrolling stitching algorithms (the product includes horizontal scrolling; the preview only simulates vertical), OCR, native text input and IME, the native window minimum width (720 pt; below it this preview switches to overflow menus), SF Symbols (Lucide icons stand in), curved arrows, full tool-style choices, Option-center drawing, multi-selection and marquee, duplicate and copy or paste of objects, and pinch or Space-drag panning.
